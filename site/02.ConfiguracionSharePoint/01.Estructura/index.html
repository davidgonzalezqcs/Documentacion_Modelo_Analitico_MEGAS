    Configuración técnica de SharePoint¶

    1. Introducción¶

    La integración con SharePoint mantiene una copia operativa del proyecto entre el servidor local y el sitio de SharePoint. El flujo descarga archivos Bronce nuevos o modificados, y sube el código, la configuración, los archivos Parquet y los logs generados por todo el pipeline desde la capa Bronce hasta la capa oro.

    La comunicación se realiza contra la SharePoint REST API clásica, mediante endpoints _api/web/.... La autenticación se obtiene con MSAL usando una aplicación de Microsoft Entra ID y un certificado, no solo un client secret.

    En pipeline.py, la sincronización ocurre en dos momentos:

    1. Después de ejecutar las fuentes API y antes de la capa Bronce, se crea la estructura remota con sync_folder_structure() y se descarga Bronce con download_Bronce_incremental().
    2. Después de ejecutar Bronce, Silver y Gold, se suben los respaldos con upload_backup_and_config() y upload_parquets_and_logs().

    El entorno se selecciona con --env prod, con PIPELINE_ENV=prod o, por defecto, se usa test.

    2. Registro de la aplicación en Azure AD¶

    En la documentación actual de Microsoft, Azure AD se denomina Microsoft Entra ID.

    2.1 Crear el App registration¶

    1. En el ambiente de Microsoft Entra ID de Megas, cree un App registration con un nombre identificable, por ejemplo Tablero MEGAS.
    2. Seleccione cuentas compatibles únicamente con el directorio organizacional de este tenant (single tenant).
    3. Conserve los identificadores que muestra el registro:
    Dato en Microsoft Entra ID Variable para test Variable para prod Uso
    Application (client) ID TEST_CLIENT_ID PROD_CLIENT_ID Identifica la aplicación ante MSAL.
    Directory (tenant) ID TEST_TENANT_ID PROD_TENANT_ID Identifica el tenant usado en https://login.microsoftonline.com/<tenant>.
    Thumbprint del certificado TEST_CERT_THUMBPRINT PROD_CERT_THUMBPRINT Vincula la autenticación con el certificado registrado en la aplicación.

    Se puede usar la misma aplicación y certificado en ambos entornos, si el equipo lo aprueba. En ese caso se repiten los valores en las variables TEST_* y PROD_*. También es posible definir una aplicación o certificado distinto para producción.

    2.2 Crear y registrar el certificado¶

    El código construye ConfidentialClientApplication con un objeto que contiene private_key y thumbprint. Por tanto, el flujo esperado es autenticación por certificado.

    Genere un par de llaves y conserve:

    • El certificado público, normalmente .cer, para cargarlo en Certificates & secrets > Certificates de la aplicación.
    • La llave privada, normalmente key.pem, para guardarla únicamente en el servidor local que ejecutará el pipeline.

    Ejemplo de generación con OpenSSL:

    openssl req -x509 -newkey rsa:2048 -keyout key.pem -out cert.pem -days 365 -nodes -subj "/CN=Tablero-MEGAS-SharePoint"
openssl x509 -in cert.pem -outform der -out cert.cer

    Obtenga el thumbprint del certificado público y elimine los espacios al copiarlo a la variable de entorno. Por ejemplo, con PowerShell:

    Get-PfxCertificate .\cert.cer | Select-Object Thumbprint, Subject, NotAfter

    La llave privada se referencia con TEST_CERT_KEY_PATH o PROD_CERT_KEY_PATH. Si no se define, el script busca 00_sources/scripts/02_sharepoint/key.pem relativo a la raíz del proyecto.

    La llave privada nunca se sincroniza

    No suba key.pem, cert.pem, cert.cer con material privado, ni ningún archivo de credenciales a Git o SharePoint. La función _is_excluded_relative_path() de sync_sharepoint.py excluye .env, credenciales.env, key.pem, credentials.json y archivos con extensión .pem, .key, .pyo o .pyc.

    3. Permisos y consentimiento de administrador¶

    La API usada por el código es SharePoint Online, no Microsoft Graph: las solicitudes se envían a rutas como _api/web/GetFolderByServerRelativeUrl(...). El administrador debe confirmar en el tenant el recurso exacto al que se asigna el permiso.

    Recurso API Tipo de permiso Permiso Por qué se necesita Quién lo otorga
    SharePoint (Office 365 SharePoint Online) Aplicación Sites.FullControl.All o el permiso mínimo equivalente aprobado por seguridad Leer y descargar Bronce; crear carpetas; subir código, configuración, Parquets y logs. Administrador de Microsoft 365 / administrador de SharePoint.

    El permiso debe autorizarse como Application permission sobre SharePoint (Office 365 SharePoint Online) y requiere Grant admin consent. Sin consentimiento de administrador, el certificado puede estar correctamente registrado y aun así la aplicación no podrá obtener un token utilizable para el sitio.

    La concesión debe gestionarse normalmente desde la administración de SharePoint, por ejemplo mediante appinv.aspx, o con PnP PowerShell usando los comandos aprobados por el administrador, como Register-PnPAzureADApp y Grant-PnPAzureADAppSitePermission. No se debe asumir que configurar permisos de API de Microsoft Graph concede acceso a los endpoints REST de SharePoint.

    Confirmar el recurso del token

    El código usa SharePoint REST, pero el valor de respaldo actual de sync_sharepoint.py es https://graph.microsoft.com/.default. Para que el token sea válido contra REST, cada variable TEST_SCOPES o PROD_SCOPES debe apuntar al recurso de SharePoint, por ejemplo https://<tenant>.sharepoint.com/.default, y no a Graph. El administrador de Microsoft 365 debe confirmar el hostname exacto, el permiso efectivo y el mecanismo de concesión en este tenant.

    Los valores se cargan desde .env y, normalmente, desde 00_sources/scripts/02_sharepoint/credenciales.env o desde el archivo indicado en *_CREDENTIALS_FILE. Use la plantilla .env.example del proyecto como referencia de nombres, si está disponible, y mantenga los valores reales fuera del control de versiones.

    4. Variables de entorno¶

    Las variables se resuelven con el prefijo del entorno seleccionado. TEST_* se usa con python pipeline.py; PROD_* se usa con python pipeline.py --env prod.

    Variable Propósito Origen del valor
    TEST_CLIENT_ID / PROD_CLIENT_ID Application (client) ID de la app registration. Microsoft Entra ID.
    TEST_TENANT_ID / PROD_TENANT_ID Directory (tenant) ID. Microsoft Entra ID.
    TEST_CERT_THUMBPRINT / PROD_CERT_THUMBPRINT Huella del certificado público registrado. Certificado cargado en la app registration.
    TEST_CERT_KEY_PATH / PROD_CERT_KEY_PATH Ruta local a la llave privada PEM. Decisión operativa del servidor; el archivo debe existir y ser legible por el proceso.
    TEST_SP_BASE_URL / PROD_SP_BASE_URL Host del tenant de SharePoint, por ejemplo https://megas9411.sharepoint.com. Configuración del tenant; el código usa este valor o el valor por defecto configurado.
    TEST_SP_SITE_PATH / PROD_SP_SITE_PATH Ruta relativa al sitio y a la biblioteca raíz del entorno. Decisión del equipo de SharePoint. Producción debe definirse explícitamente.
    TEST_SCOPES / PROD_SCOPES Recurso para acquire_token_for_client. Debe configurarse para SharePoint, por ejemplo https://<tenant>.sharepoint.com/.default; revisar la advertencia anterior.
    TEST_CREDENTIALS_FILE / PROD_CREDENTIALS_FILE Ruta a un archivo adicional de variables. Decisión operativa; si es relativa, se interpreta desde la raíz del proyecto.

    Ejemplo mínimo de rutas, sin valores secretos:

    TEST_SP_BASE_URL=https://megas9411.sharepoint.com
TEST_SP_SITE_PATH=/sites/TABLEROMEGAS/Documentos compartidos/TABLERO MEGAS/test
PROD_SP_BASE_URL=https://megas9411.sharepoint.com
PROD_SP_SITE_PATH=/sites/TABLEROMEGAS/Documentos compartidos/TABLERO MEGAS/prod
TEST_SCOPES=https://<tenant>.sharepoint.com/.default
PROD_SCOPES=https://<tenant>.sharepoint.com/.default

    El script conserva compatibilidad con nombres heredados sin prefijo, como client_id, tenant_id, cert_thumbprint y scopes_sharepoint_online. Para una configuración nueva se recomienda usar siempre las variables TEST_* y PROD_*.

    5. Estructura de carpetas sincronizada¶

    La raíz configurada en *_SP_SITE_PATH tiene esta forma:

    /sites/TABLEROMEGAS/Documentos compartidos/TABLERO MEGAS/<entorno>

    <entorno> es test o prod. Ambos ambientes conservan el mismo layout; únicamente cambia la ruta base para evitar mezclar archivos de pruebas con producción.

    Carpeta o archivo en SharePoint Carpeta o archivo local equivalente Contenido Dirección de sincronización Excluido de sincronización
    00_sources/ 00_sources/ Scripts de APIs archivos de muestra de cada fuente de archivos manuales. Subida a SharePoint; sync_folder_structure() crea sus carpetas. No, salvo credenciales, llaves, cachés y extensiones excluidas.
    01_Bronce/data/ 01_Bronce/data/ Archivos Bronce de entrada. En esta carpeta se actualizan los archivos manuales por parte de los responsables dentro de MEGAS Descarga incremental a local y subida de archivos locales modificados. No, salvo archivos excluidos por _is_excluded_relative_path().
    01_Bronce/parquet/ 01_Bronce/parquet/ Parquets de Bronce. Archivos comprimidos sin permisos directos de edición Subida a SharePoint. No para .parquet; otros tipos no son candidatos de subida.
    02_silver/data/ 02_silver/data/ Resultados Parquet de Silver. Subida a SharePoint. No para .parquet; otros tipos no son candidatos de subida.
    03_gold/data/ 03_gold/data/ Resultados Parquet de Gold. Subida a SharePoint. No para .parquet; otros tipos no son candidatos de subida.
    09_logs/ 09_logs/ Logs del pipeline, ingesta y capas. Subida a SharePoint únicamente para archivos .log. No para .log; secretos y extensiones excluidas siguen fuera.
    utils/ utils/ Utilidades Python compartidas. Subida a SharePoint. No, salvo cachés, credenciales y extensiones excluidas.
    01_Bronce/scripts/, 02_silver/scripts/, 03_gold/scripts/ Mismas rutas locales Código ejecutable de las capas. Subida a SharePoint mediante upload_backup_and_config(). No, salvo archivos excluidos.
    pipeline.py pipeline.py Orquestador principal. Subida a SharePoint mediante upload_backup_and_config(). No.
    07_config/sources.yaml 07_config/sources.yaml Configuración de fuentes. Subida a SharePoint mediante upload_backup_and_config(). No.
    07_config/mappings.yaml 07_config/mappings.yaml Mapeos de transformación. Subida a SharePoint mediante upload_backup_and_config(). No.
    Archivos de credenciales y llaves .env, credenciales.env, key.pem, archivos .pem o .key Secretos y material criptográfico. No se descargan ni se suben por las rutinas de archivos. Sí: nunca deben publicarse.

    sync_folder_structure() compara las carpetas locales con las carpetas remotas y crea las que falten. La descarga de archivos está limitada a Bronce; la subida se separa entre respaldo de código/configuración y resultados Parquet/logs.

    El layout local es el espejo del layout remoto

    La estructura de carpetas del servidor local debe ser un espejo exacto de la estructura correspondiente en SharePoint. sync_folder_structure() crea automáticamente en SharePoint cualquier carpeta local que falte. No se deben versionar ni mantener manualmente diferencias de carpetas entre ambos lados; la rutina de sincronización es la fuente operativa para crearlas.

    6. Antes de ejecutar el pipeline¶

    Se sugiere validar este check list antes de ejecutar el pipeline (orquestador principal):

    • [ ] La app registration existe en el tenant correcto y está configurada como single tenant.
    • [ ] El certificado público está cargado en la aplicación y el thumbprint coincide con TEST_CERT_THUMBPRINT o PROD_CERT_THUMBPRINT.
    • [ ] La llave privada existe en TEST_CERT_KEY_PATH o PROD_CERT_KEY_PATH y no se comparte ni se versiona.
    • [ ] SharePoint Online tiene autorizado el permiso de aplicación aprobado, como Sites.FullControl.All o el mínimo equivalente.
    • [ ] El administrador concedió consentimiento y confirmó el acceso al sitio correspondiente.
    • [ ] TEST_SCOPES y PROD_SCOPES apuntan al recurso de SharePoint, no al fallback de Graph.
    • [ ] SP_BASE_URL y SP_SITE_PATH apuntan al entorno correcto (test o prod).
    • [ ] Las variables están cargadas mediante .env o credenciales.env/el archivo indicado en *_CREDENTIALS_FILE.
    • [ ] La ejecución de prueba se valida con python pipeline.py en el ambiente de pruebas antes de usar python pipeline.py --env prod en el ambiente de producción.

    Para ejecutar:

    python pipeline.py
python pipeline.py --env prod
