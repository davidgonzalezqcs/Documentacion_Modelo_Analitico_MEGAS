    Actualización de Fuentes en el SharePoint¶

    Esta página describe cómo deben actualizarse las fuentes de entrada del modelo analítico. La usan los responsables definidos en 07_config/sources.yaml (campo owner) y quienes administran la ejecución del pipeline. La regla por defecto es simple: una fuente manual debe conservar exactamente la plantilla de referencia en 00_sources/samples/, en la misma ruta equivalente de 01_bronze/data/.

    Una actualización puede afectar todo el tablero

    La capa Bronze detiene el pipeline si falla una fuente. Silver registra el error y continúa con las demás fuentes, pero Gold solo se ejecuta si Silver alcanza al menos el 80 % de finalización. Antes de reemplazar un archivo en SharePoint, valide el nombre, la hoja, los encabezados y los tipos de dato.

    1. Introducción¶

    SharePoint es el punto de intercambio de los archivos manuales. El pipeline descarga los archivos Bronze, calcula un hash para detectar cambios y los convierte en snapshots Parquet; Bronze no transforma los datos. Después, Silver renombra y tipa las columnas según 07_config/mappings.yaml.

    2. Regla general para fuentes manuales¶

    Salvo las excepciones descritas en las secciones siguientes, toda actualización debe seguir la plantilla ubicada en 00_sources/samples/<ruta equivalente>. En la práctica significa:

    1. Mantener el mismo nombre o el mismo patrón de nombre que indica sources.yaml. Por ejemplo, **/*.xlsx permite varios archivos, mientras que 01.Formato mensual Conversión Auto GLP.xlsx exige ese nombre exacto.
    2. Mantener el mismo tipo de archivo, la misma hoja y la misma fila de encabezados. skip_rows indica las filas que el lector omite antes de interpretar los nombres de columnas.
    3. Mantener los nombres de las columnas tal como aparecen en la plantilla. mappings.yaml relaciona cada source_name con un target_name de Silver.
    4. Mantener el tipo esperado: string, integer, float, date o datetime. Las columnas required: true no deben faltar ni quedar vacías en los registros válidos; las columnas marcadas como primary_key deben identificar registros sin duplicados.
    5. Agregar los nuevos registros sin borrar el histórico, salvo que el procedimiento de la fuente indique que cada archivo representa un corte mensual independiente.

    01_bronze/scripts/get_data.py busca los archivos con el pattern, lee Excel/CSV usando sheet, skip_rows, encoding y separator, y guarda una copia Parquet. No corrige encabezados, fechas ni números. Si el patrón no encuentra el archivo, la hoja no existe o una columna no coincide, puede ocurrir una falla de ingesta; si la lectura pasa pero faltan columnas requeridas o un tipo no puede convertirse, fallará el contrato de Silver.

    Antes de cargar

    Compare el archivo nuevo con la muestra y con el último archivo de 01_bronze/data/. No cambie encabezados para hacerlos "más legibles": el nombre legible para Silver se define en target_name, no en el archivo de entrada.

    3. Fuentes por API¶

    Las siguientes fuentes tienen status: on y type: api en sources.yaml. Se actualizan automáticamente mediante los scripts de 00_sources/scripts/; no requieren cargue manual en SharePoint:

    Fuente Script Sistema / responsable
    1_3_cilindros_vigigas 01_vigigas/vigigas_api_client.py vigigas / felipe bedoya
    4_1_distribucion_trazabilidad_cilindros 01_vigigas/vigigas_api_client.py vigigas / felipe bedoya
    4_2_invoices_vigigas 01_vigigas/vigigas_api_client.py vigigas / felipe bedoya
    7_1_mb_tx_propane 03_mb_tx_propane/mb_tx_propane_api.py EIA, agencia del gobierno de Estados Unidos / responsable interno de la cuenta
    7_3_trm 04_trm/trm_api.py Datos Abiertos Colombia / responsable interno que gestione la fuente

    Ante una falla:

    1. Revise el log correspondiente en 09_logs/00_sources/, especialmente la carpeta del script (vigigas, 03_mb_tx_propane o 04_trm). Revise también el log de 09_logs/pipeline/ para ver si el orquestador continuó.
    2. Una falla transitoria suele ser un timeout, una respuesta temporalmente no disponible o un error de red. Reintente en otra ejecución y confirme si se generó el Parquet.
    3. Un error repetido de autenticación, token, 401/403, endpoint no encontrado o respuesta inválida indica credenciales vencidas, permisos o API caída. No cargue un archivo manual como sustituto sin validarlo con el owner.
    4. Para Vigigas contacte a felipe bedoya; para Propane, al responsable interno que administra la cuenta de EIA; para TRM, al responsable interno de Datos Abiertos Colombia. El owner externo indicado en sources.yaml no reemplaza el contacto operativo interno.

    4. Fuentes World Office¶

    4.1 Costo de ventas preliminar y costo de ventas final¶

    5_4_costo_ventas_preliminar recibe el export original de World Office en 01_bronze/data/05_ventas/04_costo_ventas_preliminar/entrada/, con patrón **/*.xlsx, hoja ExportarAExcel y skip_rows: 3. La muestra tiene un encabezado de reporte en las primeras filas; el script 01_bronze/scripts/01_costo_ventas_bronce.py lee todos los Excel de esa carpeta.

    El preprocesamiento hace lo siguiente:

    • Renombra y tipa las columnas preliminares
    • Elimina vendedor y documentos nulos
    • Marca duplicados
    • Identifica la línea de negocio
    • Calcula cantidad_kg, incluyendo reglas para códigos lbs/kg, litros EDS y documentos NCCL/NDCL
    • Cruza tarifas y fechas de EDS
    • Valida contra las tablas paramétricas locales

    El resultado queda en 04_costo_ventas_preliminar/por_validar/ para revisión contable (Rocío Moreno).

    Después de validar el archivo, copie el resultado final a la carpeta que consume 5_5_costo_ventas: 01_bronze/data/05_ventas/05_costo_ventas/. En la convención remota documentada, la ruta es 01_bronze/data/05_ventas/05_costo_ventas/ dentro de la raíz del entorno de SharePoint (test o prod). No deje el archivo aprobado únicamente en por_validar: Silver no procesa esa carpeta.

    El archivo final usa la hoja ExportarAExcel, skip_rows: 0 y debe contener, como mínimo, las columnas requeridas de mappings.yaml:

    • documento_contable (string)
    • fecha (date)
    • nombre_cliente (string)
    • codigo_inventario (string)
    • unidades
    • valor_unitario_venta
    • valor_venta_cop
    • valor_costo_unitario
    • total_costo_cop
    • margen
    • porcentaje_margen (float)
    • es_duplicado
    • registro_valido
    • cantidad_kg
    • linea_negocio
    • fuente_bronce (string)

    El patrón de nombre mensual observado es MM-YY COSTO DE VENTAS.xlsx; manténgalo para que la trazabilidad sea clara.

    4.2 Estado de resultados, balance general y centro de costos¶

    Los tres reportes se guardan en sus carpetas equivalentes bajo 01_Bronce/data/05_ventas/, usan **/*.xlsx, hoja ExportarAExcel y conservan además una hoja visual Tabla. Los nombres observados son MM-YY ESTADO RESULTADOS.xlsx, MM-YY BALANCE GENERAL.xlsx y MM-YY CENTRO DE COSTO AUTO GLP.xlsx. El prefijo MM-YY se usa en Silver para calcular fecha_mes, por lo que no debe omitirse ni cambiarse.

    Estos reportes pueden recibir registros manuales para conservar la estructura visual del reporte, no solo cambios de valores. La fila nueva debe respetar todas las columnas requeridas y el tipo definido en mappings.yaml:

    Cómo agregar un nuevo registro en los archivos World Office¶

    Las instrucciones siguientes aplican a cualquier fila que se agregue manualmente en la hoja ExportarAExcel de 5_6_estado_resultados, 5_7_balance_general o 5_8_centro_costos.

    Paso 1 — Determine el tipo de fila

    • Fila con cuenta contable real: tiene un código numérico en nivel_5 / CodCuentaNivel5 / Código proveniente de World Office.
    • Fila calculada o visual: no tiene cuenta contable. Use el código EXTRA_<id_registro> de la paramétrica correspondiente (tablas anteriores). Su valor numérico (Mar, TotalCodNivel5, etc.) puede quedar en cero; el tablero lo reemplaza con el resultado calculado.

    Paso 2 — Verifique que el código exista en la paramétrica

    Antes de escribir la fila, confirme que el código está en la paramétrica correspondiente. Si no existe, el registro no se cruzará en Silver/Gold y quedará sin clasificar.

    Reporte Columna del código en el Excel Paramétrica Columna de la paramétrica
    5_6_estado_resultados Texto176 / NombreCuentaNivel5 / TotalCodNivel5 dim_agrupaciones_estado_resultados.xlsx nivel_5
    5_7_balance_general CodCuentaNivel5 / NombreCuentaNivel5T / TotalCodNivel5 No tiene paramétrica directa — use solo cuentas reales —
    5_8_centro_costos Código / NombreCuentaNivel4 dim_centro_costo_auto_glp.xlsx / dim_agrupaciones_analisis_autoglp.xlsx cod_centro_costo / nivel_4

    Paso 3 — Complete todas las columnas requeridas

    • Códigos, nombres de cuenta, tercero y etiquetas: string (texto exacto, sin fórmulas).
    • Valores contables (Mar, TotalCodNivel5, Expr1014, PASYPAT, Mar4): float.
    • No deje vacíos los campos de jerarquía Texto120, Texto122, Texto123, Texto132 (estado resultados / balance) ni CodCCostos1 (centro de costos): Silver los necesita para construir los niveles.

    Paso 4 — Valide antes de guardar y subir

    1. Nombre del archivo: patrón MM-YY <NOMBRE>.xlsx con el mes y año del período.
    2. Hoja de datos: ExportarAExcel. La hoja Tabla es solo visual y no se procesa.
    3. No mueva, elimine ni renombre columnas existentes.
    4. No agregue filas de totales manuales fuera de los marcadores EXTRA de la paramétrica: los totales visuales los construye Gold.
    5. Revise que el código no esté ya en el archivo del mismo período. Silver descarta duplicados y registros sin el campo de cuenta necesario (nivel_5 o nivel_4).

    Note

    Puede revisar los archivos de meses anteriores y tomarlos como referencia para agregar los registros.

    4.3 Compras por producto y cartera por edades¶

    2_2_compras_por_producto se descarga directamente de World Office en 01_Bronce/data/02_compras_producto_glp/02_compras_por_producto/. Usa cualquier .xlsx, hoja ExportarAExcel y skip_rows: 2; los datos observados empiezan en la fila 3. Si hay que corregir un dato, conserve las columnas y el orden de meses anteriores:

    • Nombres
    • Productos
    • Fecha
    • Documento
    • Cantidad
    • Total Ingresos
    • Precio Promedio
    • Clasif_Det.

    Las seis primeras son requeridas. Fecha es date, Cantidad, Total Ingresos y Precio Promedio son float, y los demás campos son string salvo Clasif_Det, que es float cuando viene informado.

    6_1_cartera_producto se descarga en 01_Bronce/data/06_cartera_producto/, como .xlsx, hoja ExportarAExcel. El archivo observado tiene título en la fila 1, nombres reales en la fila 3 y datos desde la fila 4; por eso es una excepción semiestructurada. El clean aplana el encabezado, extrae la fecha de cierre del título y descarta TOTAL GENERAL. No cambie la disposición de las tres filas iniciales ni convierta el reporte a una tabla plana. mappings.yaml aún marca esta fuente como pendiente_diseno y el script Silver usa un contrato provisional; cualquier cambio de columnas debe validarse con el owner antes de publicarlo.

    5. Otras fuentes manuales¶

    Las siguientes instrucciones se basan en los archivos Bronze reales y en sus muestras. Para todas, actualice el archivo en la ruta equivalente de 01_Bronce/data/ y no modifique los encabezados.

    5.1 7_4_costo_embarque¶

    • Archivo: costo_embarque.xlsx — patrón **/*.xlsx
    • Hoja de datos: datos (desde la fila 2). La hoja Resumen Regulatorio es solo informativa.
    • Al actualizar:
      • Agregue la nueva fila al final de la hoja datos.
      • Mantenga una fila por período; no cambie el nombre del archivo.
    • Columnas y tipos:
      • fecha → date
      • costo_embarque, alpha → float

    5.2 7_5_costo_transporte¶

    • Archivo: costo_transporte.xlsx — patrón **/*.xlsx
    • Hoja de datos: calculo_TPCB (desde la fila 2). La hoja Resumen Regulatorio es solo informativa.
    • Al actualizar:
      • Agregue el período al final de la hoja calculo_TPCB.
      • Conserve el orden y los nombres de las siete columnas.
    • Columnas y tipos:
      • Mes de Aplicación (m), Mes del Costo TPCB (m-1), Mes Referencia IPP (m-2) → date
      • IPP (m-2), IPP Feb-08 (Base), TPCB Feb-08 (COP/kg), TPCB Calculado (m-1) [COP/kg] → float

    5.3 8_1_conversion_auto_glp¶

    • Archivo fijo: 01.Formato mensual Conversión Auto GLP.xlsx
    • Hoja de datos: Hoja1 — encabezados en fila 1, descripciones en fila 2, datos desde fila 3 (skip_rows: [1]).
    • Al actualizar:
      • Agregue filas debajo del último registro.
      • No elimine ni sobreescriba la fila 2 de descripciones.
    • Columnas y tipos:
      • Id Registro → integer (único, sin duplicados)
      • Fecha → date
      • Identificación, usuario, estado, observaciones → string

    5.4 8_2_rutas_vehiculos¶

    • Archivo fijo: 02.Formato mensual Rutas Vehículos.xlsx
    • Hoja de datos: Hoja1 — misma estructura de fila 1/2/3 que los demás formatos.
    • Al actualizar:
      • Agregue una fila por fecha y por vehículo.
      • No cambie acentos ni espacios de los encabezados.
    • Columnas y tipos:
      • Fecha → date
      • Placa, Linea negocio → string
      • Km recorridos → float
      • Conteos de eventos (tres columnas) → integer

    5.5 8_3_facturacion¶

    • Archivo fijo: 03.Formato mensual Facturación.xlsx
    • Hoja de datos: Hoja1 (datos desde la fila 3).
    • Al actualizar:
      • Agregue filas al final de la tabla.
    • Columnas y tipos:
      • Id Registro → integer (único, sin duplicados)
      • Números y estados → string
      • Fechas de proceso y creación → date
      • Observaciones → string
      • Fecha fin proceso puede quedar vacía (no es requerida), pero la columna debe existir.

    5.6 8_4_rrhh¶

    • Archivo fijo: 04.Formato mensual RRHH.xlsx
    • Hoja de datos: Hoja1 (datos desde la fila 3).
    • Al actualizar:
      • Agregue el registro del mes al final.
      • No agregue subtotales dentro de la tabla.
      • No elimine ni sobreescriba la fila 2 de descripciones.
    • Columnas y tipos:
      • Mes liquidado, Fecha creación → date
      • Cinco indicadores numéricos → integer
      • Observaciones → string

    5.7 8_5_accidentes¶

    • Archivo fijo: 05.Formato mensual Accidentes.xlsx
    • Hoja de datos: Hoja1 (datos desde la fila 3).
    • Al actualizar:
      • Agregue una fila por período.
      • Mantenga intactos los encabezados y la fila descriptiva (fila 2).
    • Columnas y tipos:
      • Id Registro → integer (único, sin duplicados)
      • Fecha, Fecha creación → date
      • Cantidades → integer
      • Observaciones → string

    5.8 8_6_simulacros¶

    • Archivo fijo: 06.Formato mensual Simulacros.xlsx
    • Hoja de datos: Hoja1 (datos desde la fila 3).
    • Al actualizar:
      • Agregue una fila por simulacro.
      • No escriba datos sobre la fila 2, que contiene las descripciones.
    • Columnas y tipos:
      • Id Registro → integer (único, sin duplicados)
      • Fecha Simulacro → date
      • Nombre, tipo, cumplimiento, observaciones → string

    5.9 8_7_saldos¶

    • Archivo fijo: 07.Formato Saldos.xlsx
    • Hoja de datos: Data (datos desde la fila 2). La hoja Resumen es una vista dinámica y no debe usarse como tabla de carga.
    • Al actualizar:
      • Agregue las filas al final de la hoja Data.
      • Actualice fecha y registros de la fuente diaria sin reemplazar los encabezados.
    • Columnas y tipos:
      • Fecha, FECHA DE PAGO → date
      • Valor, VLR CUOTA → float
      • Categoría, entidad, concepto, detalle, tipo → string
