    APIs¶

    Esta sección documenta las fuentes de tipo api que ingresan información a la capa Bronze del proyecto. La configuración declarativa de cada fuente se encuentra en 07_config/sources.yaml; los clientes de ingesta viven en 00_sources/scripts/.

    El flujo de estas fuentes es:

    API externa -> script de ingesta -> Parquet en 01_bronze/data -> capas Silver y Gold

    Fuente de verdad

    Las rutas, frecuencias, responsables y scripts indicados en esta página reflejan 
`07_config/sources.yaml`. Los endpoints y el comportamiento de extracción se describen 
a partir del código disponible en cada script y, para Vigigas, de la colección Postman asociada.

    Resumen¶

    API Fuente(s) Frecuencia Owner Script
    Vigigas 1_3_cilindros_vigigas, 4_1_distribucion_trazabilidad_cilindros, 4_2_invoices_vigigas Mensual felipe bedoya 00_sources/scripts/01_vigigas/vigigas_api_client.py
    MB TX Propane 7_1_mb_tx_propane Mensual eia - Agencia del gobierno de Estados Unidos 00_sources/scripts/03_mb_tx_propane/mb_tx_propane_api.py
    TRM 7_3_trm Mensual Datos Abiertos Colombia 00_sources/scripts/04_trm/trm_api.py

    Credenciales

    Nunca se deben documentar ni versionar valores de tokens, contraseñas o
API keys. Esta página solo indica los nombres de variables y archivos que
requiere cada cliente.

    Vigigas¶

    Propósito y fuentes alimentadas¶

    El cliente obtiene información operativa de Vigigas y la persiste en tres conjuntos Parquet de Bronze:

    Request de la colección Fuente sources.yaml Destino configurado
    GetCylinders 1_3_cilindros_vigigas 01_bronze/data/01_inventario/03_cilindros_vigigas
    GetHistories 4_1_distribucion_trazabilidad_cilindros 01_bronze/data/04_distribucion/01_trazabilidad_cilindros
    GetInvoices 4_2_invoices_vigigas 01_bronze/data/04_distribucion/02_invoices_vigigas

    Autenticación y endpoints¶

    La configuración declarada en sources.yaml es:

    ingestion:
    script: 00_sources/scripts/01_vigigas/vigigas_api_client.py
    config_env: 00_sources/scripts/01_vigigas/Collection QCS Integration.postman_collection

    El archivo existente en el repositorio es Collection QCS Integration.postman_collection.json. El script lo carga por defecto desde esa ruta con extensión .json, o permite sustituirlo con --collection.

    Request Método Endpoint
    Login POST /api/v1/user_sessions/login
    GetInvoices POST /api/v1/vigigas/getInvoices
    GetCylinders GET /api/v1/vigigas/getCylinders
    GetHistories GET /api/v1/vigigas/getHistories

    Los endpoints se resuelven desde la URL definida en la colección Postman. La autenticación es por token de sesión: authenticate() ejecuta Login, extrae el token de claves habituales de la respuesta (token, access_token, jwt, entre otras) y lo envía en el encabezado:

    Authorization: Token token=<TOKEN_DE_SESION>

    También se puede proporcionar un token mediante el argumento --token; el valor no debe escribirse en documentación ni en archivos versionados. El body de Login contiene las credenciales de la integración dentro de la colección, por lo que el archivo debe protegerse como configuración sensible.

    Funciones principales¶

    Función Responsabilidad
    load_collection() Lee y parsea el JSON de la colección Postman.
    find_request() Localiza una request por nombre dentro de la colección.
    resolve_url() / resolve_body() Obtienen la URL y el body de la request.
    resolve_bearer_token() / extract_token() Resuelven un token definido en la colección o extraen el token devuelto por Login.
    do_request() Ejecuta la petición HTTP con urllib, timeout de 30 segundos y parseo JSON; convierte errores HTTP o excepciones en un status y payload retornables.
    build_date_body() Inyecta dateInitial y dateFinal en el body de GetInvoices.
    determine_date_range() Calcula una carga inicial de los últimos 730 días o un rango incremental desde la fecha máxima histórica hasta ayer.
    flatten_record() / response_to_dataframe() Aplana objetos anidados a columnas con notación padre.hijo y serializa listas como JSON.
    save_parquet() Combina histórico y datos nuevos, elimina duplicados por fila completa, ordena por fecha y escribe Parquet.
    run_request() Orquesta una request, aplica filtros, valida la respuesta y persiste el resultado en el destino correspondiente.
    main() Procesa argumentos CLI y ejecuta un endpoint o los tres.

    No hay paginación ni reintentos automáticos implementados. GetCylinders y GetHistories se tratan como snapshots: la API devuelve todos los registros y el cliente filtra localmente los registros del día en curso. GetInvoices admite el rango de fechas en el body.

    Parámetros de entrada¶

    python vigigas_api_client.py --all
python vigigas_api_client.py --request GetInvoices --date-from YYYY-MM-DD --date-to YYYY-MM-DD
python vigigas_api_client.py --request GetCylinders --force-initial
    • --request: GetCylinders, GetInvoices o GetHistories.
    • --all: ejecuta las tres requests.
    • --date-from y --date-to: rango explícito; --date-to requiere --date-from.
    • --force-initial: ignora el Parquet existente y carga los últimos 730 días.
    • --collection: ruta alternativa al JSON de Postman.
    • --token: token de sesión opcional.

    Formato de salida¶

    Todas las salidas son Parquet y cumplen el patrón *.parquet de sources.yaml. Los nombres concretos definidos por el cliente son:

    Request Archivo Campos de fecha usados
    GetCylinders cilindros_vigigas.parquet fecha_creacion
    GetHistories trazabilidad_cilindros.parquet fecha
    GetInvoices invoices_vigigas.parquet fecha

    Los campos de negocio dependen del payload de Vigigas. Los objetos anidados se convierten en columnas como objeto.campo; las listas se conservan como texto JSON. El cliente combina el histórico con la respuesta nueva y elimina duplicados por fila completa, excepto que para snapshots no reconstruye un histórico si la extracción procede de una carga inicial.

    Frecuencia y responsable¶

    Las tres fuentes se configuran con frecuencia monthly, estado on, y owner (responsable) felipe bedoya.

    Limitaciones y notas

    - La colección contiene la configuración de autenticación y debe estar
    protegida. No se deben copiar sus valores sensibles a otros documentos.
- El script usa HTTP según la URL de la colección; la seguridad del canal
    depende de que la colección se configure con el endpoint adecuado.
- No existe paginación ni reintento ante errores transitorios.
- El rango automático de facturas termina en ayer; los snapshots aplican un
    filtro local para excluir el día actual.

    MB TX Propane¶

    Propósito y fuente alimentada¶

    Obtiene el precio spot diario de propano Mont Belvieu, Texas, publicado por la U.S. Energy Information Administration (EIA). Alimenta la fuente 7_1_mb_tx_propane.

    Autenticación y endpoint¶

    • Base URL: https://api.eia.gov/v2/seriesid.
    • Request: GET https://api.eia.gov/v2/seriesid/PET.EER_EPLLPA_PF4_Y44MB_DPG.D.
    • Autenticación: API key enviada como parámetro de consulta api_key.
    • Archivo esperado: 00_sources/scripts/03_mb_tx_propane/credenciales.env.
    • Variable esperada: EIA_API_KEY.

    El script carga el archivo con python-dotenv; el archivo está excluido de Git.

    Funciones principales y parámetros¶

    • determine_date_range(): carga inicial de 730 días o incremental desde el día siguiente a la fecha máxima del histórico.
    • fetch_propane_data(): consulta la serie, obtiene response.data, selecciona period y value, y los renombra a fecha y precio_usd_galon.
    • save_parquet(): concatena el histórico, deduplica por fecha, ordena y escribe el Parquet.
    • main(): expone --output, --force-initial, --date-from y --date-to.

    El rango puede recibirse por CLI. La API se consulta sin filtros de fecha y el rango se aplica localmente en Pandas. La respuesta está limitada por el comportamiento de la serie solicitada y no hay paginación ni reintentos explícitos en el script.

    Formato de salida¶

    Fuente Ruta configurada Archivo escrito por defecto Columnas principales
    7_1_mb_tx_propane 01_bronze/data/07_fuentes_externas/01_mb_tx_propane mb_tx_propane_history.parquet fecha, precio_usd_galon

    El formato es Parquet, con una observación por fecha y precio expresado en dólares por galón. La ruta puede cambiarse con --output, aunque la ruta predeterminada coincide con la de sources.yaml.

    Frecuencia y responsable¶

    La frecuencia configurada es monthly, el estado es on, y el owner es eia - Agencia del gobierno de Estados Unidos.

    Limitaciones y notas

    - El archivo `credenciales.env` debe existir y contener `EIA_API_KEY`; no
    se documenta su valor.
- El script filtra las fechas después de descargar la serie completa.
- Los errores HTTP de EIA se registran y producen código de salida `2`.
- La documentación del código menciona rotación de logs; la salida se
    registra en `09_logs/00_sources/03_mb_tx_propane/`.

    TRM¶

    Propósito y fuente alimentada¶

    Obtiene la Tasa Representativa del Mercado publicada en el portal de Datos Abiertos de Colombia, mediante Socrata. Alimenta la fuente 7_3_trm.

    Autenticación y endpoint¶

    • Dominio: www.datos.gov.co.
    • Dataset Socrata: ceyp-9c7c.
    • Método: GET mediante el cliente sodapy.Socrata.
    • Autenticación: consulta pública sin API key ni archivo de credenciales.

    La consulta usa SoQL sobre vigenciadesde, orden ascendente y un límite de 50000 registros:

    vigenciadesde >= 'YYYY-MM-DDT00:00:00.000' AND \
vigenciadesde <= 'YYYY-MM-DDT23:59:59.999'

    Funciones principales y parámetros¶

    • determine_date_range(): carga inicial de 730 días o incremental desde el día siguiente a la fecha máxima de vigenciadesde.
    • fetch_trm_data(): ejecuta la consulta Socrata, crea el DataFrame y tipa valor, vigenciadesde y vigenciahasta.
    • save_parquet(): concatena el histórico, deduplica por vigenciadesde, ordena y guarda el Parquet.
    • main(): expone --output, --force-initial, --date-from y --date-to.

    Formato de salida¶

    Fuente Ruta configurada Archivo escrito por defecto Columnas principales
    7_3_trm 01_bronze/data/07_fuentes_externas/03_trm trm_history.parquet valor, vigenciadesde, vigenciahasta

    El formato es Parquet. La ruta puede cambiarse con --output; por defecto coincide con el directorio definido en sources.yaml.

    Frecuencia y responsable¶

    La frecuencia configurada es monthly, el estado es on, y el owner es Datos Abiertos Colombia.

    Limitaciones y notas

    - La consulta tiene un límite fijo de `50000` registros y el script no
    implementa paginación.
- No hay reintentos explícitos ante errores de red o del servicio Socrata.
- Si el histórico no tiene `vigenciadesde`, se fuerza una carga inicial.
