# Capa Bronce

La capa Bronce conserva la ingesta de las fuentes y sus snapshots Parquet. La
excepción es `costo_ventas_bronce`, que prepara un archivo Excel para revisión
contable antes de incorporarlo como fuente definitiva.

## Parte 1: costo_ventas_bronce

### Ejecución y archivos involucrados

`01_costo_ventas_bronce.py` es el primer script de la lista `BRONZE_SCRIPTS`
de `pipeline.py`. El orquestador detiene el pipeline si falla la capa Bronce. La ejecución operativa también tiene un lanzador de Windows junto al script:

```text
01_bronze/scripts/Ejecutar_Costo_Ventas.bat
```

El script Python carga el contrato de `5_4_costo_ventas_preliminar` desde
`mappings.yaml` y la configuración de la fuente desde `sources.yaml`:

```yaml
id: 5_4_costo_ventas_preliminar
path: 01_bronze/data/05_ventas/04_costo_ventas_preliminar/entrada
pattern: "**/*.xlsx"
sheet: ExportarAExcel
skip_rows: 3
```

### Limpieza y normalización

Para cada Excel encontrado, el script aplica estas operaciones, en este orden
general:

1. Lee la hoja configurada (`ExportarAExcel`) omitiendo las tres primeras filas
	y conserva inicialmente las columnas como texto.
2. Marca `es_duplicado` sobre el DataFrame original y añade un identificador
	temporal. Después usa las funciones de preparación de Silver con el contrato
	de `mappings.yaml` para renombrar las columnas, tiparlas, eliminar
	duplicados según las columnas requeridas y retirar el identificador temporal.
3. Elimina `vendedor` y `vendedores`, si existen, y descarta las filas cuyo
	`documento_contable` sea nulo.
4. Crea `unidades_ajustada` a partir de `unidades`. Si
	`documento_contable` contiene `DMC` (coincidencia sensible a mayúsculas),
	multiplica esas unidades por `-1`.
5. Inicializa `registro_valido` en `si` y lo cambia a `no` cuando
	`codigo_inventario` no comienza por `PT` ni por `021`. 
6. Calcula `cantidad_kg`: extrae un número seguido de `kg` desde
	`codigo_inventario` (acepta coma o punto decimal, y no distingue
	mayúsculas/minúsculas) para códigos que contienen simultáneamente `lbs` y
	`kg`; para códigos que contienen `litros EDS` usa `0.540026`; en los demás
	casos usa `unidades_ajustada`. Si el documento contiene `NCCL` o `NDCL`,
	fuerza `cantidad_kg` a `0.0`.
7. Cruza `valor_unitario_venta` y `fecha` con la paramétrica
	`precio_venta_eds.xlsx`, usando `Tarifa`, `Desde` y `Hasta`, para obtener la
	estación EDS aplicable. Una tarifa con `Hasta` nulo se considera vigente.

La carpeta de paramétricas que el script lee es:

```text
01_bronze/data/05_ventas/04_costo_ventas_preliminar/00_parametricas
```

Los archivos son `clientes_granel_granjas.xlsx`, `clientes_mayorista.xlsx`,
`precio_venta_eds.xlsx` y `umbral_granel_cilindros_tame.xlsx`. Los dos primeros
se convierten en conjuntos de nombres de clientes y el último proporciona
`valor_unitario_venta_limite`.

### Identificación de `linea_negocio`

La asignación se realiza con `np.select`: se evalúan las condiciones en el
orden siguiente y gana la primera que se cumple.

| Orden | Condición implementada | Valor asignado |
|---:|---|---|
| 1 | `registro_valido` es `no` o es `False` | `No aplica` |
| 2 | `codigo_inventario` contiene `CILINDROS` | `Cilindros - Sibaté` |
| 3 | `nombre_cliente` es exactamente `LOS MORALES DE CASTILLA SAS` | `Granel - EDS Fusagasugá` |
| 4 | `nombre_cliente` es exactamente `LIVER S POOL SAS` | `Granel - EDS Melgar` |
| 5 | `nombre_cliente` pertenece a `clientes_granel_granjas.xlsx` | `Granel - Granjas` |
| 6 | `nombre_cliente` pertenece a `clientes_mayorista.xlsx` | `Mayorista` |
| 7 | El cliente contiene `CONSUMIDOR FINAL` o `CUANTIAS MENORES`, el código comienza por `021` y `unidades < 7000` | `Cilindros - SUI` |
| 8 | El mismo candidato SUI y `unidades >= 7000` | `Cilindros - Tame` |
| 9 | El código comienza por `021`, hay precio y es menor que `valor_unitario_venta_limite` | `Cilindros - Tame` |
| 10 | El código comienza por `021`, hay precio y es mayor o igual que el límite | `Granel` |
| 11 | Se encontró una estación en el cruce EDS | `Granel - <estación>` |
| Por defecto | Ninguna condición anterior | `Sin línea identificada` |

Las comparaciones de texto que usan `contains` no distinguen mayúsculas de
minúsculas; las comparaciones exactas de los clientes y las pertenencias a las
paramétricas sí se realizan sobre el texto previamente limpiado con `strip()`.
Después de asignar la línea, el script elimina sus columnas temporales, ordena
los registros y agrega filas de subtotal por línea. También escribe fórmulas
Excel `SUM` para `cantidad_kg` y `valor_venta_cop`.

### Rutas, validación y entrega

| Tipo | Fuente / destino | Ruta local | Configuración relevante |
|---|---|---|---|
| Entrada | `5_4_costo_ventas_preliminar` | `01_bronze/data/05_ventas/04_costo_ventas_preliminar/entrada` | Excel, patrón `**/*.xlsx`, hoja `ExportarAExcel`, `skip_rows: 3` |
| Salida inmediata del script | Preparación para validar | `01_bronze/data/05_ventas/04_costo_ventas_preliminar/por_validar` | Un `.xlsx` por archivo de entrada, hoja `ExportarAExcel` |
| Destino posterior a la aprobación | `5_5_costo_ventas` | `01_bronze/data/05_ventas/05_costo_ventas/` | Excel, patrón `**/*.xlsx`, hoja `ExportarAExcel`, `skip_rows: 0` |

!!! warning "Validación contable obligatoria"
	 La salida de `por_validar` es preliminar. El equipo contable debe revisar y
	 validar el archivo antes de considerarlo definitivo y trasladarlo a
	 `01_bronze/data/05_ventas/05_costo_ventas/`. El script Python y el archivo
	 `.bat` no realizan automáticamente ese traslado.

Una vez validado, el archivo debe depositarse en la carpeta correspondiente a
`5_5_costo_ventas`. `sync_sharepoint.py` conserva la misma ruta relativa bajo
la raíz configurada del sitio: la carpeta local
`01_bronze/data/05_ventas/05_costo_ventas/` se refleja como
`/01_bronze/data/05_ventas/05_costo_ventas/`. La rutina
`upload_parquets_and_logs()` incluye `01_bronze/data` entre sus carpetas de
subida y `upload_file()` calcula el destino a partir de la ruta relativa del
archivo. 

## Parte 2: resto de scripts Bronze

### Ingesta y validación común

El resto de las fuentes definidas en `sources.yaml` se procesa mediante
`01_bronze/scripts/get_data.py` y `01_bronze/scripts/validate_schema.py`. Estos
scripts importan las utilidades de `utils/transformers_bronze.py`; por tanto,
no reimplementan en cada fuente la lectura, el descubrimiento de archivos, la
generación de snapshots ni el registro de auditoría. `get_data.py` además
calcula el hash MD5, reutiliza el último Parquet cuando el archivo no cambió y
registra los estados `ok`, `skipped` o `error`. `validate_schema.py` reutiliza
la búsqueda de Parquets y la normalización de flags para validar los contratos
de `mappings.yaml`.

### Funciones públicas de `transformers_bronze.py`

| Función | Responsabilidad implementada |
|---|---|
| `normalize_flag(value, default)` | Convierte banderas a texto en minúsculas. Trata booleanos de PyYAML y los valores `true/yes/1` como `on`, y `false/no/0` como `off`; usa el valor predeterminado cuando recibe `None`. |
| `md5(path, chunk_size=8192)` | Calcula el hash MD5 leyendo el archivo por bloques, para detectar cambios sin cargarlo completo en memoria. |
| `append_audit(row, audit_log_path)` | Agrega una fila al histórico CSV sin sobrescribirlo y crea el encabezado si el archivo aún no existe. |
| `discover_files(base_path, pattern)` | Descubre archivos con el patrón glob configurado. Normaliza separadores, ordena el resultado y tiene un recorrido alternativo con expresión regular cuando `Path.glob` rechaza patrones con `**`. |
| `resolve_source_base_path(source, project_root=None)` | Resuelve la ruta base local usando `source.path` o, como alternativa, `source.output.path`. |
| `resolve_source_pattern(source)` | Obtiene el patrón desde `source.pattern` o desde `source.output.pattern`; si no existe, usa `**/*`. |
| `try_encodings(path, sep, skip_rows)` | Lee CSV probando `utf-8`, `latin-1` y `cp1252`, en ese orden, con separador, filas a omitir y columnas como texto. |
| `read_file(path, source, override)` | Lee Excel, CSV, API o Parquet según la configuración. El override por archivo prevalece para hoja y filas a omitir; en Excel usa `openpyxl` y en CSV puede autodetectar encoding. Mantiene la lectura cruda: no filtra columnas ni transforma tipos deliberadamente. |
| `parquet_path(parquet_dir, source_id, file_stem, timestamp)` | Crea la carpeta de la fuente y construye el nombre versionado `<archivo>__<timestamp>.parquet`, conservando snapshots históricos. |
| `load_mappings_notes(mappings_path, logger=None)` | Carga las notas opcionales de `mappings.yaml`, las compacta como texto por `source_id` y, si falla la lectura, registra una advertencia y devuelve un diccionario vacío. |
| `find_all_parquets(parquet_dir, source_id)` | Busca todos los Parquet de una fuente bajo su carpeta y los ordena por fecha de modificación; conserva un fallback para archivos históricos ubicados directamente en `01_bronze/parquet`. |

!!! note "Alcance de Bronze"
	 Bronze conserva la lectura cruda para las fuentes generales. Las
	 transformaciones de negocio específicas de `costo_ventas_bronce`, incluida
	 la clasificación de `linea_negocio`, pertenecen a su script especializado
	 y no a `transformers_bronze.py`.
