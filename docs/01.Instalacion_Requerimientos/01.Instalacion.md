# 1. Instalación y Configuración

Esta sección es una guía para preparar un entorno local del proyecto, conectarlo con SharePoint y enlazar el tablero en Power BI Desktop.

---

## 🖥️ Requisitos del Sistema

Para garantizar un rendimiento óptimo en el procesamiento de datos y el renderizado de las visualizaciones, se recomiendan las siguientes especificaciones de hardware y software:

* **Procesador:** Intel Core i5 / AMD Ryzen 5 (4 núcleos) o superior.
* **Memoria RAM:** 8 GB como mínimo (16 GB recomendado para optimizar los tiempos de carga).
* **Almacenamiento:** 20 GB de espacio libre (se recomienda el uso de unidades SSD).
* **Sistema Operativo:** Windows 10/11 Professional (64 bits) o Windows Server 2019 en adelante.

---

## 📦 Software Requerido

| Componente / Software | Versión Exacta | Propósito en el Proyecto |
| :--- | :--- | :--- |
| **Python** | `3.12.10` | Lenguaje para los scripts y rutinas de extracción, transformación y carga de datos. |
| **Power BI Desktop** | `2.152.1279.0` (64 bits, marzo de 2026) | Visualización del tablero, modelado DAX y procesos ETL (Power Query). |

---

## 🔧 Pasos para la Instalación y Configuración

Siga esta secuencia de pasos para poner en marcha el tablero de control en su entorno:

### 1. Instalación de software

- Descargue e instale **Python** desde su sitio oficial, en la versión indicada.
- Descargue e instale **Power BI Desktop**, preferiblemente desde la *Microsoft Store*. Esto garantiza actualizaciones automáticas y la instalación de la arquitectura correcta de 64 bits.

### 2. Instalar el código fuente

- En el servidor o equipo donde se realizará la instalación, cree una carpeta para la solución y copie allí el `.zip` con el código fuente que QCS comparte a través del SharePoint de desarrollo del proyecto. Este paquete incluye las credenciales de las APIs de Vigigas, SharePoint, precios del propano y TRM, por lo que debe manejarse con acceso restringido, ya que expone información sensible de la organización.

> **Nota:** Como parte del desarrollo de la herramienta, QCS realizó la instalación en el servidor físico de Megas, dejando un ambiente para pruebas y otro para producción.

### 3. Configurar las credenciales de SharePoint

El pipeline obtiene la configuración de conexión a la API del sitio de SharePoint previamente configurado, con los permisos ya otorgados. Esta configuración se encuentra en `00_sources/scripts/02_sharepoint`.

**Significado de las credenciales**

---
Del archivo *`credenciales.env`*:

- `client_id`: identificador de la aplicación registrada que solicita acceso a SharePoint.

- `cert_thumbprint`: huella que identifica el certificado usado por la aplicación.
- `tenant_id`: identificador del tenant de Microsoft Entra ID donde está registrada la aplicación.
- `scopes_sharepoint_online`: alcance (scope) de autenticación usado para conectarse a SharePoint Online.
- `sharepoint_base_url`: URL base del sitio del proyecto en el SharePoint de Megas.
- `PROD_SP_SITE_PATH`: ruta relativa dentro del sitio donde se encuentra el ambiente de producción en SharePoint.

---

- `key.pem`: archivo de clave privada asociado al certificado. El proceso lo lee desde la ruta configurada para autenticar la aplicación.

---
- `cert.pem`: archivo de certificado necesario para autenticar la aplicación.

!!! warning "Protección de credenciales"
	No publiques `client_id` junto con la clave privada, el contenido de `key.pem` ni los archivos `.env` o de credenciales. Mantén estos archivos fuera del control de versiones y usa valores reales únicamente en tu entorno local.

!!! note "Acceso requerido"
	Las credenciales de la aplicación no sustituyen los permisos de SharePoint: tanto la cuenta como la aplicación deben tener autorización para acceder al sitio del proyecto.

> **Nota:** Como parte del desarrollo de la herramienta, QCS realizó también la configuración del sitio de SharePoint, dejando un ambiente para pruebas y otro para producción.

### 4. Crear el ambiente virtual

Para la ejecución de los scripts se utiliza un ambiente virtual que garantiza su correcto funcionamiento. Es importante respetar las versiones definidas en `requirements.txt`.

Ubíquese en la carpeta raíz del proyecto y ejecute:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Si PowerShell bloquea la activación para la sesión actual, ejecute antes:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
```

Con el entorno activo, instale las dependencias:

```powershell
pip install -r requirements.txt
```

### 5. Ejecución

Con el ambiente virtual activado, ejecute el pipeline en el ambiente de pruebas. Esto toma los archivos del ambiente de pruebas en SharePoint, ejecuta todo el proceso en el servidor local y, al finalizar, sube una copia de los resultados al ambiente de pruebas en SharePoint:

```powershell
python pipeline.py
```

Para ejecutar en el ambiente de producción:

```powershell
python pipeline.py --env prod
```

> **Nota:** Como parte del desarrollo de la herramienta, QCS realizó la instalación en el servidor físico de Megas, dejando un ambiente para pruebas y otro para producción, además de programar la ejecución automática mensual durante los primeros 5 días del mes a las 6:00 a. m. El pipeline identifica los archivos nuevos o modificados y los actualiza automáticamente.

## 📓 Levantar la documentación local

Desde la carpeta que contiene `mkdocs.yml`, ejecute:

```bash
cd 06_docs/Documentacion
mkdocs serve
```

MkDocs mostrará la dirección local disponible, normalmente `http://127.0.0.1:8000/`.

## 📚 Verificación final

Compruebe que el entorno está activo, que las dependencias se instalaron correctamente y que la documentación puede construirse sin errores:

```bash
python --version
python -m pip check
cd 06_docs/Documentacion
mkdocs build --strict
```
